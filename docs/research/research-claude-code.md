### 1.2 Claude Code docs (code.claude.com, fetched 2026-10-16)

- Best practices. Core constraint is that context fills up and performance degrades. "Give Claude a way to verify its work" with a ladder of gates: in-prompt check, `/goal` condition, Stop hook, or a verification subagent / workflow so the worker is not the grader. Explore, plan, code, commit loop; let Claude interview you with AskUserQuestion and write SPEC.md, then execute in a fresh session; specs should name files and interfaces, state out of scope, and end with an e2e verification step. CLAUDE.md should be short ("Would removing this cause Claude to make mistakes?"); if Claude ignores a rule, "convert it to a hook". Writer/Reviewer pattern across two sessions. Reviewer prompts should say "flag only gaps that affect correctness or the stated requirements" to avoid over-engineering. https://code.claude.com/docs/en/best-practices
- Hooks. 33 events (SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, PostToolBatch, Stop, SubagentStart/Stop, TaskCreated, TaskCompleted, TeammateIdle, PreCompact/PostCompact, WorktreeCreate/Remove, FileChanged, ConfigChange, etc.). Five hook types: command, http, mcp_tool, prompt, agent. Exit 2 blocks; exit 1 is non-blocking; `"onFailure": "block"` makes hook crashes fail closed (since v2.1.295). PreToolUse can `allow|deny|ask|defer` and rewrite input via `updatedInput`. Stop/SubagentStop use `{"decision":"block","reason":...}`; `stop_hook_active` is the loop guard. https://code.claude.com/docs/en/hooks
- Hooks guide. Stop hooks are overridden after 8 consecutive blocks with no intervening tool call. Agent-type hooks (experimental) spawn a subagent with tools, 60 s default timeout and up to 50 turns, e.g. a Stop hook that runs the suite. https://code.claude.com/docs/en/hooks-guide
- Subagents. Markdown + YAML frontmatter: `tools`/`disallowedTools`, `model`, `permissionMode`, `skills` (preload), `hooks` (scoped), `memory` (user/project/local), `isolation: worktree`, `background`, `maxTurns`, `mcpServers`, `omitClaudeMd`. Subagents can nest (default depth 3). Default 20 concurrent. Subagent does not see conversation history, so restate rules in the delegation prompt. `Agent(worker, researcher)` in `tools` restricts which subagents can be spawned. Plugin-shipped subagents ignore `hooks`, `mcpServers`, `permissionMode`. https://code.claude.com/docs/en/sub-agents
- Skills. Commands merged into skills; `disable-model-invocation`, `context: fork` + `agent`, `allowed-tools`, `hooks` in frontmatter, `` !`cmd` `` dynamic injection, progressive disclosure (SKILL.md under 500 lines plus reference files and scripts). Skill content after compaction may keep only the start, so put critical instructions at the top. "Claude skipped a rule that must hold every time: move the rule into a hook." https://code.claude.com/docs/en/skills
- Headless / `-p`. `--output-format json|stream-json`, `--json-schema` (structured output in `structured_output`), `--bare` (skip hooks/plugins/CLAUDE.md for reproducible CI, will become default), `--allowedTools`, `--permission-mode dontAsk|auto`, `--permission-prompts none` (v2.1.259+), `--max-budget-usd`, `--resume <session_id>`, `total_cost_usd` in output, exit codes. Note: without `--bare`, `-p` runs the repo's hooks and `.mcp.json` even in an untrusted folder. https://code.claude.com/docs/en/headless
- Dynamic workflows. JS script (`agent()`, `pipeline()`, `parallel()`, `phase()`, `log()`, `args`) run by a runtime in the background; schema-validated agent output (5 retries); resumable by replay (completed agents return cached results, first changed prompt reruns everything after it); `Date.now()`/`Math.random()` throw to keep replays deterministic; 16 concurrent agents default, 1,000 agents and 4,096 items per run; save with `s` to `.claude/workflows/`; can ship in a plugin; "Large workflow" warning above 25 agents or 1.5M tokens; no mid-run user input ("for sign-off between stages, run each stage as its own workflow"). https://code.claude.com/docs/en/workflows
- `/goal`. Session-scoped wrapper over a prompt-based Stop hook: a small fast model judges the condition after every turn, returns met / not met / impossible. Works with `-p`. Condition up to 4,000 chars; add "or stop after 20 turns" to bound it. Evaluator only sees what is in the transcript, so require Claude to surface evidence. https://code.claude.com/docs/en/goal
- Agent teams (experimental, off by default; `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`). Lead + teammates with shared task list (file-locked claiming), mailbox, TeammateIdle/TaskCreated/TaskCompleted hooks (exit 2 to push back). Teammates are not in worktrees, so partition files. No session resumption, task status can lag, one team per session, no nesting, not available under `-p`. 3-5 teammates, 5-6 tasks each. https://code.claude.com/docs/en/agent-teams
- Worktrees. `claude --worktree <name>` creates `.claude/worktrees/<name>` on `worktree-<name>`; `.worktreeinclude` copies gitignored files; `claude --worktree "#1234"` branches from a PR; `worktree.baseRef: fresh|head`; subagents get `isolation: worktree`; isolation checks block edits and git redirects into the main checkout; cleanup sweep; locks. Hooks run with `${CLAUDE_PROJECT_DIR}` at the main checkout and `cwd` at the worktree. https://code.claude.com/docs/en/worktrees
- Agent view / background sessions (research preview). `claude agents`, `claude --bg "..."`, `claude agents --json`, `claude attach|logs|stop|respawn`; dispatched sessions auto-move into their own worktree; sessions told to commit, push, open a draft PR, never push to main. https://code.claude.com/docs/en/agent-view
- Run agents in parallel (comparison page) lists subagents, agent view, agent teams, workflows, Projects, plus `/batch` (5-30 worktree-isolated subagents), cross-session messaging, routines. https://code.claude.com/docs/en/agents
- GitHub Actions (`anthropics/claude-code-action@v1`). `@claude` interactive mode vs `prompt:` automation mode; can run a skill/plugin (`/code-review:code-review --comment`); requires write access to trigger; bots rejected unless in `allowed_bots`; `--max-turns`, timeouts, concurrency controls; commits made with default `GITHUB_TOKEN` do not trigger CI. https://code.claude.com/docs/en/github-actions
- Code Review (managed). Several parallel agents find, a verification step filters false positives, dedupe and rank by severity; never approves or blocks; reads `REVIEW.md` from the base branch only, never from the PR. https://code.claude.com/docs/en/code-review
- Plugins bundle skills, agents, hooks, MCP servers, workflows; every enabled plugin's skill/agent descriptions cost context every turn. https://code.claude.com/docs/en/plugins/overview
- Plugin evals. `claude plugin eval`: cases with graders (`regex`, `tool_used`, `tool_order`, `file_exists`, `llm`, `baseline`), 3 runs per case, no-plugin baseline arm, `--threshold`, exit code 1 for CI. https://code.claude.com/docs/en/plugin-evals
- Memory. CLAUDE.md under ~200 lines; `.claude/rules/` with `paths:` frontmatter loads on demand; project-root CLAUDE.md survives compaction; auto memory is a `MEMORY.md` index (first 200 lines / 25 KB loaded) plus topic files, shared across worktrees; both are context, not enforcement ("To block an action regardless of what Claude decides, use a PreToolUse hook"). https://code.claude.com/docs/en/memory
- Costs. Average ~$13 per developer per active day, under $30 for 90% of users; agent teams ~7x tokens when teammates run in plan mode; use Sonnet for teammates; hooks can pre-filter output; `/usage` attributes spend to skills/subagents/plugins. https://code.claude.com/docs/en/costs
- Agent SDK. Same loop/tools/hooks/subagents/MCP/sessions as the CLI as a Python/TypeScript library; Managed Agents is the hosted alternative; for other languages run `claude -p` as a subprocess. https://code.claude.com/docs/en/agent-sdk/overview
- Independent architecture analysis (arXiv 2604.14228 v2, 2026-07-02, from v2.1.88 source): one shared `queryLoop`, five compaction stages, deny-first permissions in layers, users approve ~93% of prompts (so per-action approval is weak alone), 27 hook event types of which 5 are safety related, subagent transcripts stored as sidechains, append-only JSONL transcripts. https://arxiv.org/html/2604.14228v2
- Official plugins repo (anthropics/claude-code/plugins): `feature-dev` (7-phase workflow with code-explorer/architect/reviewer), `code-review` (multi-agent with confidence scoring), `pr-review-toolkit`, `hookify`, `security-guidance` (PreToolUse warning hook), `ralph-wiggum` (Stop-hook loop), `commit-commands`. https://github.com/anthropics/claude-code/tree/main/plugins

Judgement on the field: the durable, evidence-backed parts are (a) isolation (worktree/container), (b) deterministic gates (hooks/CI/tests), (c) separate-context reviewers, (d) written specs and ledgers as handoff. The persona/swarm/"consensus" layers and unbenchmarked speed claims (SuperClaude, Ruflo) are the gimmick end. Several projects in this space died or pivoted within a year (Crystal, Vibe Kanban, spec-workflow), which argues for owning a thin harness over adopting a framework.

| Cost anecdotes (weak evidence, SEO pricing sites) | n/a | Claims of ~7x tokens for teams (consistent with Anthropic's own costs doc), one unsourced story of 49 parallel subagents burning 887k tokens/min | n/a | https://www.cloudzero.com/blog/claude-code-agents/ |

Cross-cutting findings:
1. The binding constraint is human review, not generation. Practitioner ceilings are 3-5 agents; beyond that diffs get rubber-stamped (yureki_lab, Osmani, Willison).
2. Zero merge conflicts does not mean zero integration cost: API-contract mismatches and shared state (ports, DBs, flaky tests) dominate (Rozenhek, yureki_lab).
3. Reviewers fail when they lack the plan; they approve dead code (Dalski). Reviewers also drift to approve (Anthropic harness post).
4. Scope creep is the common failure of well-meaning agents; tight acceptance criteria and non-goals plus a diff-size guard fix it (Japhet).
5. Reliability compounds: 5 handoffs at 95% each is ~77% (Japhet). Fewer, larger, independent units beat many small dependent ones.
6. Cost: Anthropic's own numbers are 4x (single agent), ~15x (multi-agent) chat tokens, ~7x for agent teams; $200 vs $9 for a harnessed vs solo app build; $20k for the compiler. Pay only where tasks are high-value and parallelisable (multi-agent research post, harness post, costs doc).

## 4. Distilled ideas to build into a Claude Code factory (22)

Ordered roughly by value-to-effort. "Where it fits" refers to an existing pipeline with implementer, reviewer, skeptic, runner and git-sync roles.

### A. Gates and enforcement

1. **Stop hook that runs the real checks and blocks until green (with loop guard).**
   Source: hooks guide and best-practices (https://code.claude.com/docs/en/hooks-guide, https://code.claude.com/docs/en/best-practices).
   How: Stop hook command runs the repo's build/vet/test script; on failure emit `{"decision":"block","reason":"<tail of failing output>"}`; read `stop_hook_active` and exit 0 to avoid loops; note the platform force-allows after 8 consecutive blocks with no tool call, so the reason text must be actionable. Use `-p` + `--bare` + project `--settings` in factory runs so hooks are deterministic.
   Why: it is the difference between a run you watch and one you walk away from; it moves "tests pass" from advice to mechanism.

2. **Hard gate in CI, hook as the fast path.** Anthropic chose a CI gate over a PreToolUse hook as its hard review gate (https://claude.com/blog/how-anthropic-secures-its-ai-native-software-development-lifecycle). Implement: local hooks for fast feedback, required CI checks for the guarantee, because hooks can be bypassed by an agent that edits settings (TDD Guard concedes bypass risk: https://github.com/nizos/tdd-guard). Why: defence in depth.

3. **PreToolUse guard that fails closed.** Deny writes to protected paths (migrations already merged, `.github/`, prod manifests, `.env`), deny `git push` to anything but the factory branch, deny `rm -rf`, and normalise via `updatedInput` where useful. Set `"onFailure": "block"` so a crashed guard blocks rather than allows (https://code.claude.com/docs/en/hooks). Combine with `permissions.deny` and sandboxing. The freeCodeCamp article's example gate blocks commits containing `.env`/`.pem` (https://www.freecodecamp.org/news/how-to-build-software-factory-with-claude-code/). Why: CLAUDE.md is advisory; a hook is not (https://code.claude.com/docs/en/memory).

4. **TaskCompleted / TeammateIdle / SubagentStop quality gates.** Exit 2 from a `TaskCompleted` hook to refuse completion until lint, tests, and a diff-size limit pass; Japhet's layered gates (format, lint, secrets, tests, diff-size guard, review agent) are the concrete template (https://dev.to/javatarz/multi-agent-development-workflows-with-claude-code-n23, https://code.claude.com/docs/en/agent-teams). SubagentStop can apply the same check to every implementer subagent in `-p` or SDK pipelines.

5. **TDD enforcement as a hook, not a prompt.** TDD Guard / Probity pattern: intercept Edit/Write, require a failing test first and one test at a time (https://github.com/nizos/tdd-guard). Superpowers adds the cultural rule that code written before its test is discarded (https://github.com/obra/superpowers). Cheaper alternative if you do not want an LLM validator: a PostToolUse hook that records whether a test file changed before a source file in the same ticket and a Stop-time check that the new tests failed on the base commit (red) then pass (green).

6. **`/goal`-style evaluator for unattended completion.** For ticket-level "done", a separate small model judges a measurable condition each turn (`npm test exits 0`, `git status clean`, plus `or stop after N turns`), and works under `-p` (https://code.claude.com/docs/en/goal). Why: completion decided by a model that is not the worker; bounded by a turn clause; evidence must be in the transcript, which forces the agent to show test output.

### B. Roles, review, and verification

7. **Adversarial verification stage (reviewers propose, skeptic refutes, refuted findings are dropped).** The dynamic-workflows post (https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/) and managed Code Review (find, verify, dedupe/rank; https://code.claude.com/docs/en/code-review) both do this. Implement: reviewers emit schema'd findings (file, line, severity, claim, evidence); a skeptic with Read/Grep only must cite code to refute; never drop high severity on doubt. Tell reviewers to flag only correctness/requirement gaps to avoid over-engineering (https://code.claude.com/docs/en/best-practices).

8. **Generator / evaluator split with a sprint contract.** Before coding a ticket the implementer writes testable acceptance criteria and a verifier agrees; the evaluator grades against hard thresholds; "any criterion below threshold fails the sprint" (https://www.anthropic.com/engineering/harness-design-long-running-apps). Tune the evaluator by reading its transcripts, finding where it diverges from human judgment, and editing its prompt, because out of the box it "talked itself into approving". Keep the evaluator only where the task exceeds what the model does reliably alone; re-test after each model upgrade and delete components that are no longer load-bearing.

9. **A plan reviewer, not just a code reviewer.** Dalski's reviewer approved a feature never wired in because it did not know the plan; the fix was a dedicated plan reviewer and giving the code reviewer the plan (https://www.codecentric.de/en/knowledge-hub/blog/autonomous-development-workflows-with-claude-code). Superpowers' two-stage review (spec compliance first, then quality) is the same idea (https://github.com/obra/superpowers). Add a "reachability" check to the spec reviewer: new code must be referenced from an entrypoint, route, or subscription.

10. **Spec-compliance review that checks "no more and no less", plus a diff-size / scope guard.** Japhet's CSV-vs-PDF scope creep and diff-size guard (https://dev.to/javatarz/multi-agent-development-workflows-with-claude-code-n23). Implement as a deterministic check (diff lines and files vs ticket estimate; files outside the ticket's declared paths) before any LLM reviewer runs.

11. **Role-restricted agents by tool and path.** Builders limited to their folders, test-writer edits only test files, validator read-only and "never fixes" (https://www.freecodecamp.org/news/how-to-build-software-factory-with-claude-code/). Implement with subagent `tools`/`disallowedTools`, `Agent(x,y)` allowlists, and a scoped PreToolUse hook in the agent's frontmatter (https://code.claude.com/docs/en/sub-agents). Why: structural separation of writer from grader.

### C. Parallelism and isolation

12. **Path-ownership manifest per ticket, planned before launching agents.** `TASK.md` contract: may edit / must not touch / done criteria; junction files (barrel exports, route tables, gateway config) are off limits in parallel and edited at integration (https://dev.to/yureki_lab/how-i-run-4-claude-code-agents-in-parallel-on-one-repo-without-chaos-5ejc). Enforce with a PreToolUse hook that reads the manifest. Rozenhek shows this removes conflicts but not contract mismatches (https://dev.to/aviad_rozenhek_cba37e0660/zero-conflict-architecture-the-8020-of-parallel-development-5aok), so also do 13.

13. **Contract-first for cross-service work, plus an integration stage.** Have an agent write the API/event contract (OpenAPI, Pub/Sub payload schema) first, make builders consume that artifact, then run an integration branch with the full suite after rebasing each branch in a serial queue (yureki_lab merge queue) or a Refinery-style bisecting merge queue where agents never push to main (https://github.com/steveyegge/gastown). Why: API field-name mismatches were the biggest integration cost (13 failures, ~2 h).

14. **Cap concurrency at what humans can review (start at 3-4), parallelise only independent work.** Evidence: ceiling of four (yureki_lab), 3-5 teammates (agent-teams docs: https://code.claude.com/docs/en/agent-teams), Osmani's review ceiling (secondary). Sort the backlog into parallel-friendly (mechanical migrations, test backfills, doc passes) and serial (core abstractions). Anthropic: multi-agent only for "high-value, heavily parallelizable tasks" (https://www.anthropic.com/engineering/multi-agent-research-system). Use workflow `parallel()` concurrency caps and `CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`.

15. **Per-agent environment isolation beyond the filesystem.** Worktrees isolate files, not ports/DBs: assign ports and scratch database names per agent through env vars (yureki_lab). For stronger isolation use a container per agent with a shared bare remote and lock-file task claiming as in the compiler project (https://www.anthropic.com/engineering/building-c-compiler); `.worktreeinclude` for env files; `WorktreeCreate` hook to run setup (https://code.claude.com/docs/en/worktrees). Consider devcontainer with read-only user settings (codecentric).

16. **Quarantine untrusted input.** Reader agents (issue bodies, web pages, PR comments, logs) have no write tools or secrets and emit a schema'd summary; actor agents act only on the summary (https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/). Matches Anthropic's own stance that boundaries are drawn around what agents can do, not what they are told (https://claude.com/blog/how-anthropic-secures-its-ai-native-software-development-lifecycle). In GitHub Actions only users with write access can trigger Claude and bots are rejected by default (https://code.claude.com/docs/en/github-actions).

### D. State, specs, memory

17. **Machine-readable feature/ticket ledger where the agent may only flip one field.** JSON list with `passes:false`, steps, and category; "it is unacceptable to remove or edit tests"; JSON because the model overwrites it less than Markdown (https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents). Pair with a progress file, descriptive commits, and `init.sh`, and a startup routine (pwd, git log, progress, smoke test) so each fresh session resumes cleanly. Gas Town's Beads is the heavier version (https://github.com/steveyegge/gastown).

18. **Interview-then-spec, executed in a fresh session; specs name files, interfaces, out-of-scope, and end with an e2e verification step.** Anthropic's recommended pattern (https://code.claude.com/docs/en/best-practices). Put the spec at a stable path so every downstream agent (implementer, spec reviewer, runner) reads the same artifact. Human sign-off at three points: story/problem, technical design, pre-PR (https://www.freecodecamp.org/news/how-to-build-software-factory-with-claude-code/); groom acceptance criteria and non-goals up front because grooming "matters more than reviewing output" (Japhet).

19. **Lean CLAUDE.md, rules by path, procedures as skills, enforce with hooks, and a lessons loop.** Keep each CLAUDE.md under ~200 lines; use `.claude/rules/` with `paths:` for scoped rules; project-root CLAUDE.md survives compaction; auto memory is shared across worktrees (https://code.claude.com/docs/en/memory). Give reasons with rules so agents can trade off (Dalski). Close the loop: after each run, an agent reads session transcripts for repeated corrections and proposes CLAUDE.md/skill edits (dynamic-workflows post mines sessions for repeated corrections; Superpowers `diagnosing-superpowers` analyses transcripts; Dalski had teams write retrospectives). Keep humans approving the proposed edits (aaddrick's "improvement loop" asks before changing the pipeline: https://github.com/aaddrick/claude-pipeline).

20. **Structured outputs between stages.** Use `--json-schema` on `claude -p` (`structured_output` field) or `schema` on workflow `agent()` calls (validated, 5 retries) so stage handoffs are parseable and gates can be deterministic (https://code.claude.com/docs/en/headless, https://code.claude.com/docs/en/workflows). aaddrick's pipeline uses 14 JSON schemas for stage outputs (https://github.com/aaddrick/claude-pipeline). Make the schema the contract between reviewer, skeptic, and merge-order writer.

### E. Evals, cost, and operations

21. **Eval harness for the factory itself.** Start with 20-50 tasks drawn from real past failures; code graders first (tests, lint, tool-use checks), LLM rubric second; run 3 trials and track pass@1 and pass^k; read transcripts before trusting scores; promote capability evals to regression suites (https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents, https://www.anthropic.com/engineering/multi-agent-research-system). For prompts/agents/skills shipped as a plugin, `claude plugin eval` gives graders, a no-plugin baseline arm, `--threshold` and CI exit codes (https://code.claude.com/docs/en/plugin-evals). Re-run on every model upgrade, and use it to delete harness components that are no longer load-bearing (harness-design post). Mutation-test your evaluators: seed known-bad diffs and check the reviewers/skeptic catch them (a shadow-mode and sampled-audit approach is what Anthropic does for new AI reviewers: https://claude.com/blog/how-anthropic-secures-its-ai-native-software-development-lifecycle).

22. **Cost and runaway controls plus a model ladder.** `--max-budget-usd` and `--max-turns` per ticket, `total_cost_usd` logged per stage, `/usage` attribution for subagents/skills (https://code.claude.com/docs/en/headless, https://code.claude.com/docs/en/costs). Cheap models (Haiku/Sonnet) for runners, explorers and classification; strongest model for design and adversarial review; `CLAUDE_CODE_SUBAGENT_MODEL` or per-agent `model`. Pre-filter noisy output with a PreToolUse `updatedInput` hook (test output reduced to failures) and have the test harness print terse output with details in files, as in the compiler project. Run a one-directory pilot before a full fan-out (workflows doc). Add a stuck-agent monitor (Gas Town "Witness": https://github.com/steveyegge/gastown) and idle/`needs-input` notifications (ccmanager hooks: https://github.com/kbwo/ccmanager; `claude agents --json`: https://code.claude.com/docs/en/agent-view).

### Things to deliberately not copy

- Swarm/consensus/"queen" topologies and unbenchmarked speed claims (Ruflo, SuperClaude): unverified.
- Running pipelines with permissions disabled outside a sandbox (aaddrick README warns the same).
- Letting the lead agent also write code (Dalski: it bypassed specialist gates).
- Agent Teams for unattended production runs: experimental, no resumption, task status lags, not available under `-p` (https://code.claude.com/docs/en/agent-teams). Prefer scripted `claude -p` pipelines or dynamic workflows, which are resumable and put the plan in code (https://code.claude.com/docs/en/workflows).
- Adopting a framework wholesale: several tools in this space (Crystal, Vibe Kanban, spec-workflow) were deprecated or sunset within about a year, and Anthropic is shipping equivalents natively (`claude agents`, `--worktree`, `/batch`, dynamic workflows, `/goal`). Own a thin harness over primitives that Anthropic documents.
